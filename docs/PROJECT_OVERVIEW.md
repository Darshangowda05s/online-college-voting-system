# Project Overview

## Purpose
This repository implements a college election web application with a React (Vite) frontend and an Express/MongoDB backend. It supports admin and student flows: creating elections, voting, viewing results, and admin auditing.

## High-level architecture
- Frontend: `client/` — Vite + React app handling UI, auth, and API calls.
- Backend: `server/` — Node.js (ESM) + Express API, MongoDB models, auth and business logic.
- Docs: `docs/` — API specs and documentation (this file included).

## Data models (summary)
- `User` — stores user profile, role (admin/student), auth identifiers (email, googleId), hashed password if used.
- `Election` — election metadata, options/candidates, start/end times, status.
- `Vote` — references to `User` and `Election` and the chosen candidate/option.
- `RefreshToken` — stores refresh tokens for issued JWT refresh flow.

## Auth flow
- Frontend obtains tokens via `POST /auth/login` (or Google OAuth flow).
- Backend issues an access JWT and a refresh token (stored server-side and/or as cookie).
- Protected routes use `authMiddleware` to verify access tokens; admin-only routes also use `adminMiddleware`.

## API highlights
See `docs/openapi.yaml` for a full spec. Main endpoints:
- `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout` — auth token lifecycle.
- `GET /elections`, `POST /elections`, `PUT /elections/:id` — election CRUD (admin where required).
- `POST /elections/:id/vote` — cast a vote (student role).
- `GET /results/:electionId` — fetch results and tallies.

## Running locally (development)
Open two terminals: one for the backend and one for the frontend.

Backend (server):

```powershell
cd server
npm install
npm run dev
```

Frontend (client):

```powershell
cd client
npm install
npm run dev
```

Notes: The backend `dev` script uses `nodemon server.js` (see `server/package.json`). The frontend uses Vite (`client/package.json` scripts).

## Seed data
To populate sample data for development, run the seed script:

```powershell
cd server
node src/scripts/seed.js
```

(Ensure `MONGODB_URI` is set in your `.env` before seeding.)

## Environment variables
Typical `.env` values required by the backend:
- `MONGODB_URI` — MongoDB connection string.
- `JWT_SECRET` — secret for signing access tokens.
- `REFRESH_TOKEN_SECRET` — secret for refresh tokens (if separate).
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — for Google OAuth (if used).
- `PORT` — backend port (defaults to `3000` or as defined).

## Deployment notes
- Build the client with `npm run build` inside `client/` and serve the static files via a static host or from the Express server if configured.
- Ensure env vars are set in production and DB is reachable. Use HTTPS for auth flows.

## Troubleshooting
- Backend fails to connect: verify `MONGODB_URI` and that MongoDB is reachable.
- CORS errors: check `server/src/app.js` CORS config and frontend API base URL in `client/src/services/api.js`.
- Auth issues: verify clocks (JWT expiry), secrets, and refresh token handling.
